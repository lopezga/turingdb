LOS MOTORES
TuringDB y Neo4j: qué cambia
Ambos almacenan nodos, relaciones y propiedades. Su arquitectura y la forma de ejecutar consultas son diferentes. El motor más rápido depende de la consulta, los índices, la memoria y la estructura del grafo.


Cuándo puede destacar cada motor




Neo4j · consultas puntuales
Cuándo: localizar un nodo concreto y consultar unas pocas conexiones.
Por qué: puede utilizar un índice para encontrar el nodo y seguir sus relaciones, leyendo solo una parte pequeña del grafo.
Ejemplo: «Dame los proveedores de esta empresa».


TuringDB · análisis de muchos datos
Cuándo: calcular rankings, agrupaciones o analizar una parte grande del grafo.
Por qué: organiza las propiedades en columnas y procesa muchos valores juntos. Esto aprovecha mejor la caché de la CPU y las instrucciones que operan sobre varios valores a la vez, reduciendo el trabajo por dato.
Ejemplo: «Calcula qué proveedores tienen más conexiones en toda la red».




Son ventajas esperables, no garantías. Importa cuántos datos toca realmente la consulta, además de los índices, la memoria y las conexiones del grafo. Con 70.000 nodos, ambos pueden destacar en tareas distintas. Los ejemplos ilustran casos de uso; el catálogo actual de la demo no incluye consultas específicas de proveedores.


Más información: índices de Neo4j · almacenamiento columnar de TuringDB.

LA COMPARACIÓN
Cómo interpretar los tiempos
Se ejecutan consultas equivalentes de forma secuencial y con orden alterno. Se separa la interpretación del lenguaje del tiempo del motor. Cada tiempo incluye transporte, driver y materialización de resultados; se muestran las muestras, la mediana y el p95.
Las cachés no se vacían. La igualdad se comprueba sobre las filas devueltas; un ranking limitado no representa todo el grafo. El catálogo permite de una a diez muestras: son mediciones de demostración, no una conclusión estadística general.
Cada dataset tiene su propio servicio de Neo4j y TuringDB, con los mismos límites por motor. Los servicios comparten el ordenador: no deben ejecutarse cargas ni otras comparaciones durante una medición. El bloqueo de la API impide dos comparaciones simultáneas.


Dos tamaños, dos estructuras distintas. Offshore Leaks contiene registros empresariales históricos. Epinions es una red completa de confianza con 75.879 usuarios y 508.837 enlaces dirigidos. Compararlos permite explorar dos cargas, pero no aislar el efecto del tamaño ni reproducir por sí solo los grafos de una empresa.




TECNOLOGÍAS DEL PROYECTO
Qué utiliza esta demo




Python y FastAPI
Backend, API de consultas, validación con Pydantic y mediciones con reloj monotónico. Uvicorn sirve la aplicación.


HTML, CSS y JavaScript
Interfaz sin framework, pestañas independientes, tablas de resultados y exportación JSON.


Grafos interactivos en SVG
Visualizador común para los dos motores: nodos, relaciones dirigidas, zoom, movimiento e inspección de propiedades. Las lecturas visuales y la exploración adicional se hacen fuera de la medición.


Neo4j Community 5.26.0
Un servicio por dataset, driver oficial de Python y protocolo Bolt.


TuringDB 3.1
Un servicio por dataset y SDK Python nativo; resultados recibidos como DataFrames de pandas.


Ollama y Qwen2.5 3B
Interpretación local por CPU. El modelo elige intención y parámetros de un catálogo; el backend compila consultas de lectura. Hay un modo sin LLM y un proveedor de API intercambiable.


Docker Compose y WSL2
Servicios Linux y volúmenes persistentes. En Windows, Docker Desktop utiliza WSL2. Los servicios se arrancan manualmente.


JSONL y SHA-256
Archivos comunes de importación y verificación íntegra de propiedades, identificadores y extremos de relaciones.


ICIJ y Stanford SNAP
Datos reales con atribución y manifiestos de procedencia. Epinions contiene solo IDs y enlaces, sin nombres ni reseñas.






Proyecto de demostración. Los resultados dependen del dataset, la consulta y los recursos. El tiempo del intérprete se mide por separado.
